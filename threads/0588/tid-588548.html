It is possible only with PVars, here's an example snippet:
pawn Code:
CMD:setvar(playerid, params[]) {

    if(!IsPlayerAdmin(playerid)) return 0;
    new
        temp_Player,
        temp_Type,
        temp_pVar[32],
        temp_Value[60]
    ;
    
    if(sscanf(params, "rcs[32]s[32]", temp_Player, temp_Type, temp_pVar)) {
    
        SendClientMessage(playerid, 0xFF0000FF, "USAGE : /setvar [playerid] [Type] [pVar] [Value]");
        return SendClientMessage(playerid, 0xFF0000FF, "Type : i = Integer, s = String, f = Float");
    }
    if(!IsPlayerConnected(temp_Player))
        return SendClientMessage(playerid, 0xFF0000FF, "ERROR : Player is not connected!");

    switch(temp_Type) {
    
        case 'i' : SetPVarInt(temp_Player, temp_pVar, strval(temp_Value));
        case 'f' : SetPVarFloat(temp_Player, temp_pVar, floatstr(temp_Value));
        case 's' : SetPVarString(temp_Player, temp_pVar, temp_Value);
        default : return SendClientMessage(playerid, 0xFF0000FF, "ERROR : Invalid type!");
    }
    format(temp_Value, sizeof(temp_Value), "Player var : %s updated!", temp_pVar);
    return SendClientMessage(playerid, -1, temp_Value);
}

It is possible to put zcmd commands under callbacks, if you want to ignore the parameter warnings, you've to just fill them.
pawn Code:
public OnCallback(playerid) {

    cmd_setvar(playerid, "0 i Money 5000");
    return 1;
}
You can try the 'e' specifier of sscanf to split and store data into your enumerator.
