( Last edited by Babul; 31.12.2012 at 18:41. )
i added a temporary download link in my sig, this script is FAR BEYOND from being perfect.
you need all upward mentioned plugins/includes.
i have set the maximum spawned objects at a time to 1200, if some players want to spawn some fireworks and they dont work, then the reason is maybe the "cache" already being filled with maximum objects. the script will simply not create more then.
have a look on these lines:
Code:
const Accuracy=80;//timer(ms)
new ObjectsMax=1200;
changing the timer to a bigger value will make the moving effects look jittering - 80 ms is ok, but 50 would look better... but eats more cpu indeed...

plugins required:
<sscanf2>
<streamer>
<mapandreas>
<gvar>
<directory>

its not compiled it with the 2.8.x version of sscanf2, you may need to recompile it in case you are using the latest version.
tip: use the <JIT> plugin aswell.

@BodyBoardVEVO and others who get warnings 203 and 204:
this script is an late alpha version - it got changed, bugged, fixed,rescripted, adopted to new natives, in-& excluded from using the streamer.
the warnings about non-used variables CAN be ignored without any doubt, they will jsut eat some more RAM.
this 2.0 "edit" of the script already contains a feature which is still bugged: player-seeking effects, but i removed all fireworks using that, cause the playerid-0 bug is still existent ><

concerning the heap/stack usage:
in the compiler run options, there is a string with the pawncc.exe options, add this to it to increase the value in cells:
Code:
-S65536
..and i have to admit: i compiled with the -w203 -w204 options. ty for reminding me on removing the warnings when releasing such a script.

..this script manually moves objects by setting their positions, this causes some speed settings be loo low, but its still functional. some effects could look sort of weird.
